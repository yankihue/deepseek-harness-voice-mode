## 1. What was built

An always-on voice layer for the DeepSeek Harness: speech in/out via ElevenLabs,
dispatching to REAL harness threads (never a parallel agent brain), with threads
reporting back over spoken announcements.

```
Browser UI (static client module)
  ├─ mic → AudioWorklet → Int16LE PCM16k → WebSocket ─┐
  └─ mp3 playback per utterance, barge-in duck/cancel │
                                                      ▼
Host orchestrator (static composition plugin, Node)
  ├─ HTTP JSON RPC   POST /__dsh-voice/rpc/<method>          (control plane)
  ├─ WS route        /__dsh-voice/ws?t=<one-time-token>      (data plane)
  ├─ IntentRouter    one small llm.stream call per utterance (strict JSON verbs)
  ├─ ThreadManager   create/message/interrupt/summarize via agents/subagents/sessionQuery
  ├─ SpeakQueue      priority preemption, coalescing, drop caps, caption mirror
  └─ subprocess ──►  voice-link helper (dependency-free Node 22)
                       ├─ Scribe v2 Realtime STT socket (VAD commit)
                       ├─ TTS stream-input socket (eleven_flash_v2_5)
                       └─ RFC6455 impl: handshake, framing, masking, close
```

ElevenLabs sockets are OUTBOUND-only from the helper; API key resolves from the
harness credentials service at spawn and never reaches the browser.

## 3. Verified claims (each reproducible)

1. **Voice round-trip works against live ElevenLabs**: `ELEVENLABS_API_KEY=<key>
   node voice-link/m0-driver.js /tmp/m0.raw "start a thread"` → prints partials,
   `COMMITTED "Start a thread that fixes the flaky login tests."`, `TRANSCRIPT MATCH ✓`,
   writes `/tmp/m0-out.mp3` (valid mp3, ffprobe-checkable).
2. **100/100 offline tests**: `cd voice-link && node --test`.
3. **Static load**: server log shows `[voice.orchestrator] activated`; page HTML
   references `/plugins/deepseek-voice-mode-ui/client.js?rev=…`.
4. **RPC plane**: use the same-origin browser client; HTTP RPC rejects non-loopback and cross-origin requests.
   → `{ok:true, helper:{running:true,…}, threads:<N>}`.
5. **Hard power-off kills everything**: config.set enabled:false → helper process gone
   (`pgrep -f voice-link` empty), FSM disconnected; re-enable respawns.
6. **Threads are real**: threads.list returns actual harness sessions with titles;
   created threads appear in the normal sidebar and accept messages/interrupts.
7. **Browser E2E voice round-trip works live** (2026-08-23, Firefox, page at
   `127.0.0.1:3080`): press `Alt+Shift+V` → mic → AudioWorklet → WS tunnel →
   helper → ElevenLabs STT → `partial` echoes back live → `committed` transcript
   (`"Voice test. Hello? Voice test."`) → real thread created → TTS reply
   delivered ("Working on it.", thread lifecycle announcements). Full trace in
   `voice.state.get` captions; helper log folded in during debugging ([h] lines).
8. **Protocol hello gate is the single point of failure** for any un-gloved
   client (see H9): bridge drops every browser frame before
   `{type:'hello', proto:1, token}` (debug level, invisible). Both the original
   client bundle and the earlier probe WS client were missing hello — the
   tunnel itself was always healthy.

| H7 | **Boot race**: helper spawn can race credentials-file read at cold boot (seen once; helper exited, power-cycle heals). Fix queued: retry spawn when resolve() late-returns empty. | low | |
| H8 | m0-driver + import markers are dev scaffolding shipped inside the tree. Harmless; exclude from production packaging. | cosmetic | |
| H9 | **Client never sent protocol `hello`** — bridge gates ALL browser frames pre-hello (debug-level drop, invisible in captions). Symptom: perfect client trail (`ws:ok→mic:ok→sent`), `conn:true` server-side, zero STT. Fix: bundle `ws.onopen` sends `{type:'hello', proto:1, token}` (token from `voice.handshake`, same one in the WS URL). Found via temporary info-level forwarding of helper logs into captions. | fixed ✓ | keep the gate (it is correct) |
| H10 | **Voice agents never JOINED an agent preset** — `meta.agentPreset` only records the header; the agent publishes on the "empty global layer" (only process-wide `voice_say`; every real tool call → `UNKNOWN_TOOL`). Fix: `agents.create` `setup(agentCtx)` = `async () => { await agentPresets.mount(agentCtx, undefined) }` (deployment default, same as the GUI). Subtleties: MUST return nothing (a returned mount result carries a non-callable `.commit` → `?.commit is not a function`) and MUST be awaited (unawaited mount races the first prompt assembly → step 1 still sees voice_say-only). | fixed ✓ | verified: test voice thread ran `bash` → `echo VOICE_TOOLS_OK`, completed |
| H11 | **Voice agents had no `cwd`** — persona assembly dies with `{{cwd}} has no value` (sessions land in `_no-cwd/`). Fix: `meta.cwd` = newest real session cwd (refresh-derived), fallback `sandboxPolicy.workspaceRoot`. | fixed ✓ | |
| H12 | **No TTS sound in browser** — playback `AudioContext` created inside the WS message handler, outside any user gesture → blocked by Firefox/Chrome autoplay policy; server-side TTS always looked healthy. Fix: seed/resume the context inside `pttToggle` + document `pointerdown`/`keydown`. | fixed, audible confirmation pending | |
| H13 | **Voice was never conversational** — routed messages landed in threads but nothing spoke the *answer* back; only priority-1 acks ("Got it.") and status announces existed. Fix: reply watches (`state.replyWatch`) — every voice-sent message (create/message/route_current) arms a watch on the target session, gated on `agent/inbox/claimed` for the exact message id (so a question spoken mid-turn never grabs the current turn's text); the `session/event` firehose accumulates `assistant/message` texts; on `agent/status idle` the last non-empty text is spoken at priority 0. `route_current` pins `conversationId` (bare answers); other threads get an "On …" prefix. Stale acks pending ≥ armedAt are dropped; the following "is idle" announce is suppressed; 20-min lifetime cap. | fixed, needs live conversation round | |
| H14 | **Echo loop / cut-off in ambient mode** — the open mic hears our own TTS → `stt.partial` → client `bargeIn()` cancels the reply mid-sentence (very plausible cause of the earlier green→gray cut-off once audio worked). Fix: client suppresses mic forwarding (`mic.suppress`) while TTS utterances are actually playing (per-utterance `play.activeCount`, released on last buffer `onended`, on `tts.canceled`/`tts.error`, and on no-buffer decodes); URL `?t=` handshake unchanged. | fixed, verify during conversation round | |

convention matched exactly (incl. `./package.json` export requirement); hard power
semantics via settings; event-driven announcements with no idle LLM usage.

## 5. How to use (user manual)

- **Sidebar bottom-left mic button** = power. Off = no process, zero ElevenLabs usage.
- **Bottom-right pill** = status (dot color + level bars + caption snippet). Click =
  panel: threads (status chips, interrupt ■), captions history, ambient listen toggle,
  power row.
- **Ambient input** (chosen permanent mode): press the **composer 🎙** once or hit the
  hotkey once → listening starts (button turns ⏹ / pill turns red); speak; VAD commits
  when you pause; press again to stop.
- **Hotkey** (Settings → Voice → hotkey, e.g. `Alt+Shift+V`): single press toggles
  listening on/off. In-page scope (window must be focused).
- **`/voice on|off|status|say <text>`** text command always available.
- Spoken verbs: "start a thread that …" / "what's running?" / "stop <thread>" /
  "summarize <thread>" / anything else falls through to your current thread as a
  normal message.
- Threads report back aloud (throttled ≥8s, coalesced, capped) when watched.
- **Conversation**: speak a question → it lands in the current chat → the answer is
  spoken back (bare). Message a named/running thread → its final answer is spoken
  with an "On …" prefix. Mic is suppressed while a reply plays (no echo loops);
  speak again when it finishes. The pill shows `·v15` on the new client bundle.

## 6. How to share / install (GitHub repo recipe)

Repo root = this directory. Suggested layout already matches:
```
deepseek-voice-mode/
  README.md            ← point at REVIEW.md §5 usage
  PLAN/PROTOCOL/RESEARCH/STATUS.md
  voice-link/          (helper + tests + driver; add package.json bin later)
  packages/orchestrator/{host.js, plugin.cjs*, INTEGRATION.md}
  packages/client/{client.js, lib/*, package.json, UI-NOTES.md}
```
Install steps to document:
1. Clone anywhere; note absolute path.
2. Append to `~/.dsh/profiles/web/cordis.patch.yml`:
```yaml
- insert:
  - id: deepseek-voice-mode
    name: <ABS>/packages/orchestrator/plugin.cjs
  - id: deepseek-voice-mode-ui
    name: deepseek-voice-mode-ui
```
3. `mkdir -p ~/.dsh/profiles/web/node_modules && ln -s <ABS>/packages/client
   ~/.dsh/profiles/web/node_modules/deepseek-voice-mode-ui`
4. Put key in `~/.dsh/.credentials.yaml`: `refs: { ELEVENLABS_API_KEY: sk_… }`
5. Restart the profile; watch for `[voice.orchestrator] activated`; run §3 checks.
Rollback: remove the insert block + symlink; restart.
(Production path later: publish both packages properly and replace symlinks.)
